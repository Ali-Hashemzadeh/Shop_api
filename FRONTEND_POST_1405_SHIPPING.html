Iran Post 1405 shipping: frontend changes

The backend commit 6363419 (feat(shipment): Iran Post 1405 postal pricing engine) changes what the storefront and admin panel have to do. Read this before the backend goes live. Breaking for postal method codes.

What changed

The postal codes post_standard and post_express no longer work. They are never returned by GET /api/v1/shipment/methods, and sending them to checkout gives a 422. Frontend code that hard-codes them will break checkout as soon as the backend is deployed.
Postal methods
The two generic codes are replaced by the official Iran Post 1405 services (for example post_registered_parcel and post_intercity_d3_parcel).
Every postal method has its own price
Each price is calculated for the customer's current cart and address, so different methods have different prices.
price can be null
A postal method that can't be priced comes back with available:false, price:null and an unavailable_code.
Itemised breakdown
New price_breakdown object: base, surcharges, 10 % postal tax and a 50,000-toman packaging fee.
New checkout 422s
items.{SKU}.weight_grams when a product has no weight. shipment_method_code or address_id when the method is unavailable.
Unchanged
Local delivery, in-person pickup, the payment flow, request bodies and every existing response key.

All money is still integer tomans. Every method now has currency: "TOMAN".

Frontend checklist

Storefront (customer website)

  • Remove every hard-coded post_standard / post_express from the checkout. Render the method list the API returns.
  • Null-check price before formatting it. null means "not available", not "free".
  • Only let the customer select methods with available === true. You can show unavailable ones greyed out.
  • Show each postal method's own price. Don't copy one price to all postal options.
  • Re-fetch /shipment/methods after any cart change and any address change.
  • Handle unavailable_code, especially weight_missing, inside_local_delivery_area and destination_incomplete.
  • Handle the new checkout 422 keys: items.{SKU}.weight_grams, shipment_method_code, address_id.
  • Don't add postal tax or packaging on top of shipping_cost. They are already included.
  • Show estimated delivery from the method title, such as «پیشتاز D+3». estimated_min_days / estimated_max_days are null for the new postal methods.
  • Optional: show price_breakdown on the checkout, order detail and shipment tracking pages.
  • Keep Persian labels for the old codes so order history still renders («پست عادی» / «پست سفارشی»).
  • Make sure a guest's cart has been merged into the user's cart before you load shipping methods (see below).

Admin panel

  • Make weight_grams clearly visible on the variant form, and treat it as effectively required. A variant without a weight blocks postal checkout for every cart that contains it.
  • Remove any UI that edits or shows the post_standard / post_express price.
  • Optional: show price_breakdown in the admin shipment detail.

GET /api/v1/shipment/methods?address_id={id}

The URL, auth (auth:sanctum) and query parameters are the same. The response is different:

BeforeNow
post_standard, post_express with a fixed price from configThe Iran Post 1405 services, each priced live from the 1405 tariff
Postal price was the same for every cartPostal price depends on the cart weight and the destination
price was always an integerprice is int | null
The price is calculated from the logged-in user's server-side cart. The endpoint reads the authenticated user's cart. It does not read the X-Session-Id guest cart. If a guest just logged in on the checkout page, merge the guest cart first. Otherwise the methods are priced for an empty or stale cart and come back with cart_empty.

Unchanged methods

local_delivery and in_person_pickup work exactly as before. They have a static integer price and price_breakdown: null. The local-delivery slot flow is untouched. Without an address_id, the list still returns only methods that need no address (pickup).

Every existing key is kept. The new keys are always present (null where they don't apply), so the response shape stays the same.

If no postal method is available, checkout must still work with local delivery or pickup when they are available. Show an empty state only when no method at all has available === true.

When to re-fetch the method list

Postal prices now depend on the cart and the address. A cached list will show the wrong price, and checkout charges the server's price.

  • After an item is added or removed, or a quantity changes.
  • After the selected address changes, or the address is edited.
  • After login, once the guest cart has been merged.
  • After a checkout 422 on shipment_method_code (see checkout).

If the customer had already chosen a method and it disappears or becomes available:false after a re-fetch, clear the selection and ask them to choose again.

POST /api/v1/orders (checkout)

The request body is unchanged: shipment_method_code, address_id, delivery_slot_id?, notes?. Send one of the new codes from the method list. 

{
  "shipment_method_code": "post_standard",      // ✗ 422 now
  "shipment_method_code": "post_intercity_d3_parcel",
  "address_id": 42
}
  • Never send a price. The server recalculates shipping with the same engine as the method list and ignores any price you send.
  • The response shipping_cost equals the price shown in the list for the same cart and address.
  • shipping_cost already includes the 10 % postal tax and the 50,000 packaging fee. tax_amount stays 0. Don't add them again in the order summary.
  • total_amount = items − discounts + shipping_cost, the same as before.

address_idThe address has no province or city, or it's invalid.Send the customer to edit the address.

Payment no change

POST /api/v1/payments/initialize and the Zarinpal callback are unchanged. The payable amount is still the order's total_amount, which already includes the full postage.

Order & shipment pages

New orders

shipment_snapshot on new postal orders adds price_breakdown, tariff_year, rate_zone, weight_grams, currency and delivery_surcharge_rule ("tehran_alborz" / "metropolitan" / null). You can show the same breakdown on the order detail page.

Shipment resources

GET /api/v1/shipments/{code}, GET /api/v1/orders/{order}/shipment, the shipment inside the order detail, and the admin shipment endpoints all add price_breakdown. It is null for old orders and for local delivery / pickup.

Old orders legacy

  • Old orders still carry method_code: "post_standard" | "post_express" and their original shipping_cost, with no breakdown. They are never repriced.
  • Keep a label mapping for them: post_standard → «پست عادی», post_express → «پست سفارشی».
  • Treat a missing or null price_breakdown as normal: show only shipping_cost.
  • A pending old order can still be paid at its original price.

Admin panel changes

Product weight is now critical. A variant with an empty or zero weight_grams makes every postal method unavailable for any cart that contains it, and blocks postal checkout. The weight is never treated as 0.
  • Variant form (create/update variant, nested product create/update): weight_grams is a whole number of grams, never kilograms. The API still accepts null, but the admin UI should mark it as required, or at least warn loudly when it's empty.
  • Consider a "missing weight" filter or badge in the product list so operators can find the gaps.
  • Remove any setting or display of the old post_standard / post_express prices. Postal prices are no longer configured per method.
  • Admin shipment detail (/api/v1/admin/shipments/{code}): you can render the new price_breakdown.
  • Turning postal services on or off and route coverage (D+1, D+2, same-day, urban) are server env settings. There is no admin API for them, so there's nothing to build.

TypeScript types

export type ShipmentMethodType = 'postal' | 'local_delivery' | 'in_person_pickup';

export type PostalUnavailableCode =
  | 'service_disabled' | 'unknown_service' | 'content_not_eligible' | 'derived_tariff_unresolved'
  | 'cart_empty' | 'weight_missing' | 'weight_not_supported' | 'origin_not_configured'
  | 'destination_incomplete' | 'inside_local_delivery_area' | 'route_not_supported'
  | 'zone_unclassified' | 'carton_size_unknown' | 'carton_too_large' | 'tariff_missing'
  | 'pricing_parameter_missing';

export interface ShippingPriceBreakdown {
  base_price: number;
  extra_weight: number;
  delivery_surcharge: number;
  large_province_surcharge: number;
  island_surcharge: number;
  fragile_surcharge: number;
  electronic_service_charge: number;
  compensation: number;
  postal_tax: number;
  packaging: number;
  total: number;           // === ShipmentMethod.price
}

export interface ShipmentMethod {
  code: string;            // render what the API returns — don't hard-code
  title: string;           // Persian for postal methods
  type: ShipmentMethodType;
  price: number | null;    // ⚠ null = unavailable postal, NOT free
  requires_address: boolean;
  requires_delivery_slot: boolean;
  supports_tracking: boolean;
  estimated_min_days: number | null;   // null for 1405 postal
  estimated_max_days: number | null;
  available: boolean;
  unavailable_reason: string | null;   // English
  unavailable_code: PostalUnavailableCode | null;
  currency: 'TOMAN';
  tariff_year: number | null;
  scope: 'non_priority' | 'specialized' | 'urban' | 'intercity' | null;
  package_kind: 'envelope' | 'packet' | 'parcel' | 'bag' | 'bundle' | null;
  weight_grams: number | null;
  rate_zone: 'same_province' | 'neighbor' | 'non_neighbor'
    | 'metropolis' | 'province_center' | 'other_city' | null;
  price_breakdown: ShippingPriceBreakdown | null;
  missing_weight_skus?: string[];  // only when unavailable_code === 'weight_missing'
  pickup_location?: unknown;          // unchanged, pickup only
}

// Formatting helper — never format a null price as 0
export const formatShippingPrice = (m: ShipmentMethod): string =>
  m.price === null ? 'ناموجود' : `${m.price.toLocaleString('fa-IR')} تومان`;

// Extract SKUs from a checkout 422
export const missingWeightSkus = (errors: Record<string, string[]>): string[] =>
  Object.keys(errors)
    .map((k) => /^items\.(.+)\.weight_grams$/.exec(k)?.[1])
    .filter((s): s is string => !!s);

Release coordination

Ship the frontend at the same time as the backend. As soon as the backend is live, post_standard/post_express return 422. An old frontend that hard-codes them, or formats price without a null check, will break checkout.
  1. Before release, the shop team must fill in weight_grams for every variant. Otherwise postal will be unavailable for those products.
  2. Deploy the backend and the frontend together.
  3. Smoke test: with an Ahvaz address and a 910 g cart, post_intercity_d3_parcel should show 176,500 tomans. Place an order and check that shipping_cost equals the listed price.
  4. Check that an old order with post_standard still renders correctly in order history.
